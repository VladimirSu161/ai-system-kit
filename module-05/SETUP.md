# SETUP — мастер настройки видео-цеха HyperFrames

Инструкция для **агента ученика** (Claude Code). Проведи пользователя по шагам
от нуля до первого отрендеренного ролика. Выполняй шаги сам, спрашивай только
то, что может дать лишь пользователь (ник канала, фото для персонажа, «ок»).
После каждого крупного шага — одна строка о результате, без простыней.

Комплект рассчитан на **macOS** (скрипты используют Homebrew, `screencapture`,
системный bash). На Linux/Windows потребуется адаптация — честно предупреди
пользователя, если он не на Mac.

---

## Шаг 0. Что спросить у пользователя ДО начала (один заход, не по одному)

1. **@ник Telegram-канала** — пойдёт в CTA-сцену каждого ролика
   (формат `@ник · Telegram`). Если канала нет — любой его @ник, поменять можно потом.
2. **Фраза-описание канала** — одна короткая строка под заголовком CTA
   (пример-образец: «AI-инструменты, скиллы и автоматизации»).
3. **Какой подход к аватару он хочет:**
   - «живая голова» — он монтирует себя поверх тёмной темы в CapCut;
   - «рисованный персонаж» — светлая тема, нужна генерация персонажа (шаг 7);
   - «просто инфографика» — можно жить вообще без аватара.
   По умолчанию собираются ОБЕ темы — этот ответ влияет только на шаг 7.

## Шаг 1. Зависимости

```bash
# Homebrew (если нет): https://brew.sh
brew install ffmpeg node
node -v && ffmpeg -version | head -1
```

Python-библиотека для обработки стикеров (системным python3):

```bash
/usr/bin/python3 -m pip install --user Pillow
```

## Шаг 2. Разложить проект

Скопируй папку `hyperframes-kit` из скачанного модуля в домашнюю папку
пользователя как `~/hyperframes`:

```bash
cp -R <путь-к-скачанному>/module-05/hyperframes-kit ~/hyperframes
cd ~/hyperframes
git init && git add -A && git commit -m "HyperFrames: стартовый каркас"
```

Git обязателен: история проекта живёт в коммитах, ручные файлы-копии запрещены
правилами проекта.

## Шаг 3. Puppeteer (скрины и автопроверка рамок)

```bash
cd ~/hyperframes && npm i puppeteer
```

Качает свой Chrome (~150 МБ). Нужен скриптам `scripts/shot.mjs` (скриншоты
сайтов для вставки в ролики) и `scripts/check-highlights.mjs` (автопроверка
рамок-подсветок).

## Шаг 4. Скиллы движка HyperFrames

```bash
cd ~/hyperframes && npx --yes hyperframes@0.7.26 skills
```

Появится папка `.agents/skills/` со скиллами движка (hyperframes, gsap, three
и др.) — их читают агенты при вёрстке. Если команда не сработала — запасной
вариант: `npx skills add heygen-com/hyperframes`.

## Шаг 5. Установить скилл конвейера

Скопируй `hf/SKILL.md` из модуля в `~/.claude/skills/hf/SKILL.md` и перезапусти
сессию Claude Code, чтобы скилл подхватился:

```bash
mkdir -p ~/.claude/skills/hf
cp <путь-к-скачанному>/module-05/hf/SKILL.md ~/.claude/skills/hf/SKILL.md
```

## Шаг 6. Персонализация под канал пользователя

Подставь ответы из шага 0 вместо плейсхолдеров:

1. Во всех файлах проекта замени `@ваш_канал` на реальный @ник
   (файлы: `CLAUDE.md`, `templates/*.html`, `shared/*.css` — там это в
   комментариях, `past-videos/_reference-video64.html`):
   ```bash
   cd ~/hyperframes && grep -rl "@ваш_канал" --exclude-dir=node_modules . \
     | xargs perl -pi -e 's/\@ваш_канал/\@РЕАЛЬНЫЙ_НИК/g'
   ```
2. В `CLAUDE.md` (раздел «CTA-сцена») впиши фразу-описание канала вместо
   формулировки про «задаётся при настройке» — она должна стоять там явно.
3. **Скрин шапки канала** для CTA-карточки → `assets/cta/tg-channel.jpg`:
   открой канал в Telegram Web и сними шапку (название + число подписчиков),
   либо попроси пользователя прислать скрин. Без этого файла CTA-сцена
   покажет пустую рамку.

## Шаг 7. Персонаж и стикеры (для светлой темы Sticker Light)

Если пользователь выбрал «живую голову» или «просто инфографику» — шаг можно
отложить: тёмная тема работает без персонажа. Для светлой темы:

1. Открой `themes/sticker-light-prompts.md` — там весь порядок и готовые
   промпты. Пользователь в Nano Banana Pro (или другом генераторе картинок):
   - генерирует **character sheet** по своим 2–3 фото;
   - по нему — **11 поз** из таблицы (имена файлов из таблицы обязательны:
     `pose-base.png`, `pose-wave.png` и т.д. — шаблоны ссылаются на эти имена);
   - **стартовый банк стикеров** из таблиц (можно не все сразу — минимум
     5–10 штук, остальные догенерируются под конкретные ролики).
2. Пользователь кладёт сырые PNG в `inbox/stickers/`, ты обрабатываешь каждый:
   ```bash
   /usr/bin/python3 scripts/sticker-prep.py inbox/stickers/файл.png assets/character/pose-имя.png   # позы
   /usr/bin/python3 scripts/sticker-prep.py inbox/stickers/файл.png assets/stickers/имя.png          # стикеры
   ```
3. **Каждый результат посмотри глазами** (Read): анатомия поз без артефактов,
   заливка не съела части рисунка. Брак — на перегенерацию.
4. Каждый стикер **сразу внеси в `assets/stickers/manifest.json`**
   (`file`, `label`, `description`, `use`, `aliases`) — подбор стикеров для
   роликов идёт только по манифесту.

## Шаг 8. Смоук-тест рендера

```bash
cd ~/hyperframes && scripts/smoke-test.sh
```

Первый запуск скачает движок и может идти несколько минут. Посмотри
`renders/smoke-frames/frame-1.png` и `frame-2.png` глазами (что должно быть —
в шапке скрипта). Кадры в порядке → пайплайн жив.

Транскрипция при первом ролике сама скачает модель Whisper (~500 МБ) — это
разовая загрузка, предупреди пользователя.

## Шаг 9. Первый ролик

1. Пользователь записывает голос 50–90 секунд (тема любая), режет паузы в
   монтажке и кладёт файл в `~/hyperframes/inbox/` (можно и чистое аудио
   с диктофона — паузы тогда лучше вырезать заранее).
2. Он говорит «/hf» или «сделай ролик» — дальше работает скилл `hf`:
   звук → слот → сториборд → вёрстка → превью → рендер.
3. Готовые файлы: `~/Desktop/Ролики HyperFrames/video-01-final.mp4`
   (+ `-light-final.mp4`, если собиралась светлая тема).
