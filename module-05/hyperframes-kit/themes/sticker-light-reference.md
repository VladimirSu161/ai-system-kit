# Sticker Light — референс темы (v1, 2026-07-30)

Вторая тема HyperFrames: светлый кадр, рисованный аниме-персонаж автора
с банком поз, стикеры die-cut, белые iOS-карточки, караоке чёрным капсом.
Источник дизайна — покадровый разбор рилсов референс-автора (автор, который собирает такие же ролики кодом).

**С 2026-08-03 — светлая версия КАЖДОГО ролика.** Обе темы собираются по
умолчанию (`composition-light.html` в слоте очереди, см. CLAUDE.md «⚠️ ТЕМЫ
РОЛИКА»); автор отбирает удачную версию глазами на Рабочем столе.

**Ключевое отличие от dark-amber:** живой аватар НЕ нужен. Ролик собирается
целиком из кода: голос (запись автора или TTS) + рисованный персонаж.
Никакого наложения в CapCut.

## §1. Палитра и типографика

| Токен | Значение | Роль |
|---|---|---|
| `--bg` | `#F4F5F7` | фон кадра |
| `--ink` | `#16181D` | основной текст, активные слова караоке |
| `--muted` | `#8E939B` | вторичный текст |
| `--ghost` | `#C7CBD1` | будущие слова караоке |
| `--red` | `#E5484D` | отрицания, аннотации, «минус-цифры» |
| `--mark` | `#FFE14D` | жёлтый маркер ключевых слов |
| `--blue / --green / --orange / --purple` | см. CSS | иконки чек-листов, теги |

Шрифты: Inter (текст, караоке 900 CAPS), JetBrains Mono (терминал).
Карточки: белые, radius 30, тень `--card-shadow`. Без неона и glow —
«дорогая» лёгкость достигается тенями и воздухом.

## §2. Компоновка кадра (1080×1920)

```
y    0–110   воздух
y  110–870   ИНФОЗОНА (.info-zone): карточки / стикеры / терминал / мокапы
y  880–1030  КАРАОКЕ  (#cap-band)
y  960–1920  ПЕРСОНАЖ (.char-zone: left 100, w 880, h 950, низ кадра)
```

- `.floor-grid` — статичный перспективный пол, вставлять ПЕРВЫМ в `#root`.
- `.ui-scrim` — сразу после пола (с 2026-08-04, есть в шаблоне): мягкое
  затемнение низа и правого края, чтобы белые иконки и подпись
  TikTok/Reels/Shorts не растворялись на светлом фоне. НЕ удалять.
- Контент НИКОГДА не заходит в зону персонажа (y > 1030) и не перекрывает
  караоке. Плашка-«ответ» может висеть у головы персонажа (y 1000–1100,
  x по центру) — как пилюля «и есть ли он вообще?» в референсе, не чаще
  1–2 раз за ролик.
- rb-chip из dark-amber в этой теме НЕТ.

**UI-зоны площадок (с 2026-08-04, ОБЯЗАТЕЛЬНО):** поверх ролика TikTok/
Reels/Shorts рисуют свой интерфейс, и он закрывает наш контент:

```
ПРАВАЯ КОЛОНКА  x 940–1080, y 840–1750  — лайк/коммент/шер/аватар
НИЗ КАДРА       y 1690–1920             — подпись, ник, прогресс-бар
```

- ТЕКСТ и смысловые элементы (цифры, бейджи, стикеры-объекты) в эти зоны
  не ставить. Персонажу и фону — можно (их частичное перекрытие не ломает
  смысл). Карточки в инфозоне (y ≤ 870) правой колонки не касаются — там
  иконки ещё не начались.
- Караоке-группы центрированы и при ≤20 символах в эти зоны не попадают;
  следить за аномально длинными словами при вычитке CAP.
- `scripts/qa-frames.sh` рисует обе зоны красными рамками на каждом
  QA-кадре — проверка глазами обязательна (§8).

> в ролик** — банк генерился нейросетью, артефакты анатомии возможны и в
> других файлах. Это дешевле, чем переделывать рендер.

**Правила смены поз:**
- Хелпер `poseSwap(outId, inId, at, D=0.25)` — чистый opacity-кроссфейд.
  ❌ НЕ crossfade() — он зумит, персонаж «дышит» масштабом.
- Поза меняется на смысловом бите (отрицание → stop, вопрос → think…),
  а не по таймеру. Ритм: каждые 3–6 секунд; НЕ чаще 1 раза в 1.2с.
- В начале ролика `tl.set("#pose-<стартовая>", {opacity:1}, 0)`.
- Разметка в композиции: `.char-zone` — один `.clip` на весь ролик,
  внутри все позы `<img class="pose">`.

## §4. Караоке-субтитры

Тот же `buildCaptions(CAP)` из `shared/helpers.js`, но со светлыми opts:

```js
buildCaptions(CAP, {
  activeColor: "#16181D",
  idleColor:   "#C7CBD1",
  glow:        "0 0 0 rgba(0,0,0,0)",
});
```

- CSS темы сам делает CAPS (`text-transform: uppercase`) — текст в CAP
  оставлять как в транскрипте.
- **Выделения** — руками в CAP при вычитке (тайминги не трогать):
  - `hl:"mark"` — жёлтый маркер: ключевые слова/термины (СКИЛЛЫ, REMOTION).
    Не более 1–2 маркеров на предложение.
  - `hl:"red"` — красное: отрицания («НЕ», «НЕТ») и негативные цифры.
- Порядок работы тот же, что в dark-amber: `scripts/captions-from-transcript.mjs`
  → вычитка ошибок Whisper построчно → массив CAP в композицию.

## §5.1. Стикер-пайплайн (ОБЯЗАТЕЛЬНО на этапе сториборда)

Аналог логотип-пайплайна dark-amber. Порядок при каждом новом ролике:

1. Читая транскрипт, на каждый смысловой бит подобрать визуал по приоритету:
   интерфейс/цифры → карточка-мокап (P1/P4/P5) · бренд → SVG-иконка из
   `assets/icons/` (manifest.json, докачка `scripts/fetch-icons.mjs`) ·
   абстракция (время, деньги, рост, идея…) → стикер из `assets/stickers/`.
2. Каталог банка = **`assets/stickers/manifest.json`** (с 2026-08-03; раньше был
   `ls`, но по именам не видно, что на картинке — на 30+ файлах это лотерея).
   У каждого стикера там описание, сценарий применения и `aliases` для поиска.
   Новый стикер вносится в манифест СРАЗУ при добавлении в банк, иначе для
   следующих роликов его как бы нет. Чего не хватает —
   ВЫПИСАТЬ автору промпты по базовому шаблону из
   `themes/sticker-light-prompts.md` (раздел «Стикеры»), подставив {OBJECT}
   по-английски. Стиль в шаблоне зашит — менять только {OBJECT}.
3. Не блокироваться: пока автор генерит, верстать с временным эмодзи
   в `.sticker-col` (font-size 120px) — после генерации заменить на PNG.
4. Новые PNG обработать как банк поз: срез белого фона заливкой от краёв
   (НЕ нейромоделью remove-background — она портит светлые заливки
   полупрозрачностью), трим по альфе, сохранить в `assets/stickers/`.
5. Лимиты: на ролик 6–10 уникальных стикеров, на экране одновременно 1–2.
   Догенерация — 2–4 штуки на ролик максимум; если нужно больше — пересмотреть
   сториборд, вероятно перебор стикеров там, где нужны карточки.
6. Банк перевалил за ~30 файлов → завести manifest.json по образцу иконок.

**Композиционные приёмы со стикерами** (из разбора 10 рилсов автора-референса):
- Пара «A → стрелка → B»: два стикера + стрелка `.ann-stroke`/синяя — причина-следствие
  (посты → контент-завод). Сильнее одиночной иконки, когда речь о превращении.
- «До/после» одного объекта: тот же стикер меняет состояние (сундук целый →
  треснутый) через crossfade — микро-сюжет без нового ассета.
- Бейдж-«статус» на стикере: маленькая `.tag` прямо у объекта («×6», «−1 час»),
  а не отдельным элементом кадра.

## §6. Движение и плотность

- Entrance: `pop` (карточки, стикеры), `slideUp` (строки, чипы). Стаггер 0.1–0.3с.
- Непрерывное движение — то же правило, что в dark-amber: ≥1 на блок
  (`typewriter`, `counter`, `drawPath`, fillBar).
- Смена блока инфозоны ≈ каждые 4–7 секунд (реже, чем сцены dark-amber:
  постоянный персонаж сам держит динамику позами).
- Стикеры: вход `pop`, замена через `crossfade` (для стикеров зум уместен),
  уход `fadeOut`. Вход можно обогатить поворотом: `fromTo(rotation:-8 → 0,
  back.out)` одновременно с pop — стикер «прилепляется», а не появляется.
- События в кадре по-прежнему ≥1 в 2–3 секунды (слово-маркер, поза,
  пункт чек-листа, тик счётчика — всё считается).

**Идл-движение (с 2026-08-04) — кадр никогда не замирает полностью:**

- **Персонаж «дышит» весь ролик:** `breathe("#char", 0, <длительность>)` —
  медленный float ±6px, цикл 2.4с. Ставится один раз, есть в шаблоне.
  Между сменами поз персонаж больше не выглядит стоп-кадром.
- **Стикеры покачиваются:** `wobble("#id", start, dur)` — ±2.2°, цикл 1.6с,
  на время окна стикера. Для die-cut наклеек это «наклеенность»; карточкам
  и терминалу wobble НЕ ставить (интерфейс не должен шататься).
- **Долгие карточки (>5с в кадре)** можно оживить `breathe(id, at, dur, 4)` —
  амплитуда 4px, едва заметный float. На короткие блоки не ставить: у них
  и так есть entrance + непрерывное движение.
- Оба хелпера строят конечный `repeat` из `dur` — правило движка
  «никакого repeat:-1» соблюдено внутри, руками ничего считать не надо.

## §7. Звук

Правила dark-amber действуют: ТОЛЬКО `whoosh` (смена блока инфозоны,
volume 0.55–0.7) + `counter` (тики счётчика, 0.5). На появления карточек,
стикеров и смену поз звук НЕ вешать.
