# Reference Theme — "Dark Amber Grid" v2

Тёмная вертикальная тема для коротких объяснительных видео (Reels/Shorts).
**Главный принцип:** крупная типографика + постоянное движение во всех кадрах.
Нет статичных моментов — всегда что-то считается, заполняется, печатается,
загорается, рисуется.

---

## 1. Фон

```css
--bg: #050505;
--bg-vignette: radial-gradient(ellipse 70% 55% at 50% 42%,
                rgba(255,255,255,0.045) 0%, transparent 65%);
--grid-color: rgba(255,255,255,0.05);
--grid-size: 64px;
```

Чёрный + перспективная сетка 64px + слабый радиальный vignette в центре.
Иногда vignette может подкрашиваться цветом сцены (низкая прозрачность).

## 2. Палитра акцентов (расширенная в v2)

Каждая сцена — **один акцентный цвет** на ключевое слово. Цвета чередуются
между соседними сценами для ритма.

```css
--accent-orange: #E8742C;     /* hook, CTA */
--accent-blue:   #5B8BFF;     /* счётчики, технические сцены */
--accent-amber:  #F5B544;     /* setup, иконки родителя */
--accent-green:  #3DD68C;     /* схождение, успех */
--accent-pink:   #FF6B9D;     /* доп. цвет для grid-cells (v2) */

--text-primary:  #F5F5F5;
--text-muted:    #8A8A8A;
--text-faint:    #4A4A4A;
```

Финальный «кульминационный» приём — **радужный градиент** по одному слову
(orange → amber → green → blue). Использовать ОДИН раз за видео, обычно
на сцене-результате.

## 3. Типографика — БОЛЬШЕ (v2 главный фикс)

```css
--font-display: "Inter", system-ui, sans-serif;
--font-mono:    "JetBrains Mono", ui-monospace, monospace;

/* размеры на холсте 1080×1920 — увеличены в v2 */
--hero-num:     380px / 0.88 / 900;   /* «99%», «1247», «5» в счётчиках */
--h1:           116px / 0.98 / 900;   /* hook, CTA-заголовок */
--h2:            92px / 1.02 / 800;   /* большинство заголовков */
--h3:            64px / 1.08 / 800;   /* подзаголовок-объяснение */
--body:          40px / 1.40 / 400;   /* основной текст */
--card-title:    44px / 1.15 / 800;   /* заголовок карточки */
--card-sub:      24px / 1.0  / 500;   /* mono подпись карточки */
--eyebrow:       26px / 1.0  / 500;   /* mono в пилюле */
```

**Правила:**
- Заголовок всегда **black 800–900**, плотный leading 0.98–1.08.
- `font-variant-numeric: tabular-nums` для всех счётчиков.
- Текст-тень `text-shadow: 0 0 60px currentColor;` на hero-числах для свечения.
- Цветной акцент — на одну фразу/слово.
- Точка в конце заголовка — часть ритма.

## 4. Eyebrow-ПИЛЮЛЯ (v2 новое)

Вместо плоского mono-eyebrow — **пилюля с обводкой и цветной точкой**:

```html
<div class="pill">
  <span class="pill-dot"></span>AGENT HARNESS
</div>
```

⚠ **Содержимое пилюли — единый тег-рубрика на весь ролик** (короткая тема,
1–3 слова), ОДИНАКОВЫЙ во всех сценах (напр. «AGENT HARNESS», «ОРКЕСТРАЦИЯ
МОДЕЛЕЙ»). **НИКОГДА** не писать в пилюле служебную разметку раскадровки —
номер сцены, тип/функцию сцены (ХУК / CTA / СРАВНЕНИЕ / ШАГ N / СЦЕНА N):
это внутреннее, зритель такого видеть не должен. Если подходящего тега нет —
пилюлю можно вообще убрать.

```css
.pill {
  display: inline-flex; align-items: center; gap: 12px;
  padding: 14px 28px; border-radius: 100px;
  background: rgba(255,255,255,0.04);
  border: 1px solid rgba(255,255,255,0.14);
  font: 500 26px/1 "JetBrains Mono", monospace;
  letter-spacing: 0.16em; text-transform: uppercase;
  color: var(--muted);
  box-shadow: 0 0 0 1px rgba(0,0,0,0.4);
}
.pill-dot {
  width: 10px; height: 10px; border-radius: 50%;
  background: var(--accent-orange);   /* меняется под сцену */
  box-shadow: 0 0 12px var(--accent-orange);
}
```

Точка в пилюле окрашивается в **акцентный цвет сцены** (orange/blue/amber/green).

## 5. Layout-паттерны (A–N; J–M добавлены в v3, N — в v4)

### A. Big-number HERO
Гигантская цифра по центру (380px), пилюля сверху, короткое уточнение снизу.
Часто с **счётчиком 0→N**.

### B. Headline + card list
Заголовок верх-лево (h2), ниже 2–4 карточек.

### C. Card list (крупные карточки)
- Padding 36×40px, border-radius 22px (увеличено в v2).
- Icon-square 96×96 в squircle с brand-цветом фона.
- Заголовок 44px bold + подзаголовок 24px mono uppercase.
- **Активная карточка** — обводка цветом акцента + glow `box-shadow: 0 0 32px var(--accent)/0.25, inset 0 0 0 1px var(--accent)/0.45`.

### D. Connector (app → app) — SVG draw
Две квадратные иконки + изогнутая SVG-линия, **рисующаяся через
`strokeDashoffset`** (см. §7 motion).

### E. CTA-блок
Большая карточка с typewriter-эффектом «АГЕНТ_», мигающий курсор,
оранжевая обводка с пульсирующим glow.

### F. Centered statement
Один заголовок в центре кадра, без карточек. Для кульминаций.

### G. Hero-диаграмма «1 → 5 → 1» (v2 новое)
Гигантские цифры (280px) и стрелки (120px), pop-in одна за другой,
каждая в своём акцентном цвете. Используется в hook для визуализации
паттерна в одном кадре.

### H. Cell-grid с подсветкой (v2 новое)
Сетка 8×N клеток (`aspect-ratio: 1/1`, gap 14px). Часть клеток
«загорается» **разными цветами** последовательно (stagger 0.1–0.15с)
— визуализирует параллельную работу N агентов. Снизу — счётчики
«САЙТОВ · 1247» и «ИДЕЙ · 89» (анимация 0→N).

### I. Two-column stat comparison (v2 новое)
Два больших столбца бок-о-бок (`gap: 20px`), каждый со своим
акцентом-обводкой + hero-num 180px (анимированный счётчик)
+ progress-bar (заполняющийся `scaleX 0→1`). Используется для
«часть совпадёт / часть разойдётся», «было / стало», и т.п.

### J. Particle-converge — частицы собираются в слово (v3, банк Remotion)
2D canvas: сотни частиц слетаются с краёв кадра и формируют слово/лого
(напр. «AI»). Сильный hook с «ИИ-вайбом», движение через GSAP timeline.
Блок: `blocks/fx-particle-converge.html`.

### K. Scramble / decode заголовок (v3, банк Remotion)
Заголовок «расшифровывается» из случайных символов в финальный (стаггер
слева направо). Технологичный акцент на GSAP.
Блок: `blocks/fx-scramble-text.html`.
⚠ Финал центрировать (`text-align:center`, `width ≤960px`, `font-size ~84px`) —
длинные заглавные на 1080px легко уходят за край (проверено).

### L. Animated bar chart (v3, банк Remotion)
Несколько баров растут снизу (`scaleY 0→1` стаггером) + counter над каждым.
Для статистики/роста. Блок: `blocks/chart-bars.html`.

### M. Animated donut (v3, банк Remotion)
SVG-кольцо заполняется по дуге (`stroke-dashoffset`) + counter % в центре.
Для доли/процента. Блок: `blocks/chart-donut.html`.

### N. Живой холст — state-machine сцена (v4, референс DevOps404)
Одна длинная сцена 20–40с вместо нарезки на слайды: статичная «рамка»
(карточка сервера / системы / пайплайна) стоит на месте, а внутри неё
объекты **живут**: заезжают в пунктирные слоты (`.slot`), меняют
состояние (`setState`/`setTag`: зелёный RUNNING → красный FAILED),
дрожат при ошибке (`shake`), переезжают (gsap x/y), реплицируются.
Камера статична, меняется состояние системы — зритель следит за
историей одного объекта, это смотрится дороже листания слайдов.
Для сюжетов «как работает X», «что происходит, когда Y ломается»,
«путь данных/задачи через систему».

Правила:
- **Цвет = состояние**: ok/warn/fail из статусной палитры (§9,
  `.box-*`/`.st-*` + хелперы) — драматургия без слов: система жила →
  заболела → починилась.
- **Событие состояния каждые 2–3с** (появление/переезд/смена статуса/
  стрелки трафика) — плотность не проседает, простой холста запрещён.
- Фигуранты — **узнаваемые логотипы** из `assets/icons/`
  (недостающие докачать: `node scripts/fetch-icons.mjs <бренды>`).
- **Достоверные детали** в mono-подписях: `CPU: 8 vCPU · RAM: 16 GB`,
  статусы, полоски утилизации — конкретика вместо абстракции.
- По метрике плотности сцен живой холст считается за
  `длительность/6` сцен (см. CLAUDE.md); переходы в/из холста —
  обычные из палитры, внутри холста переходов нет.

### 7.2 Словарь движения — приёмы по типам контента (3 яруса)

**Как пользоваться:** для каждой сцены подбирай приём из таблиц ниже.
Ярус 1 — основа (используется всегда). Ярус 2 (SVG-момент) — минимум **1 момент
на ролик**. Ярус 3 (3D) — **максимум 1 момент на ролик** (хук или кульминация).
Для сложного easing/3D — скиллы `gsap` / `three`.

#### Ярус 1 — GSAP / CSS (по умолчанию, всегда доступен)

| Контент              | Приём                              | API           |
| -------------------- | ---------------------------------- | ------------- |
| Числа (стат, цены)   | Счётчик 0→N                        | `counter()`   |
| Прогресс             | scaleX 0→1, transform-origin:left  | `fillBar()`   |
| Соединение узлов     | strokeDashoffset → 0               | `drawPath()`  |
| Поле ввода / search  | typewriter + мигающий каретик      | `typewriter()`|
| Стаггер карточек     | 0.1–0.18с между                    | вручную loop  |
| Стаггер клеток       | 0.10–0.15с                         | вручную loop  |
| Pulse glow (иконки)  | yoyo:true repeat:1–2 на boxShadow  | `tl.to()`     |
| Подсветка карточек   | yoyo по очереди в такт нарратива   | `tl.to()`     |
| Текст-акцент (слово/заголовок) | сплит на `<span>` по буквам/словам + stagger | вручную loop + `tl.from()` |
| Появление «с характером» | ease `back.out` / `elastic.out` / `expo.out` вместо power | `tl.fromTo()` |
| Фон-дрейф / parallax | медленный непрерывный transform слоёв (y/scale = f(time)) | `tl.to(...)` с конечным repeat: `Math.ceil(duration/cycle)-1`, yoyo:true (`repeat:-1` ЗАПРЕЩЁН) |
| Точка, бегущая по линии | MotionPathPlugin ведёт точку вдоль того же `path`, что `drawPath()` | `gsap` + MotionPathPlugin (бесплатен) |
| Hook-слово / лого    | сборка частиц в форму (§5 паттерн J) | блок `fx-particle-converge` |
| Декод заголовка      | scramble символов → финал (§5 паттерн K) | блок `fx-scramble-text` |
| Статистика / чарт    | бары растут стаггером / донат по дуге (§5 L, M) | блоки `chart-bars`, `chart-donut` |
| Смена сцены          | crossfade / wipe (§7.6) | блок `fx-scene-transitions` |

> Скилл `gsap` — для сложного easing, MotionPath, тонкого тайминга.

#### Ярус 2 — SVG-момент (фигурная графика) · ≥1 момент на ролик

Инлайн `<svg>` в сцене: линии рисуются `drawPath()`, узлы/фигуры загораются
`fadeIn`, непрерывное движение — yoyo-пульс (`attr:{r:...}` / glow).
Эталон с готовым кодом: `blocks/svg-network.html`.

| Момент                     | Приём                                        |
| -------------------------- | -------------------------------------------- |
| Связи / узлы / сеть / команда агентов | сеть узлов (эталон `svg-network`) |
| Схема / поток / пайплайн   | flow-узлы + drawPath-стрелки (паттерн D)     |
| Доля / процент             | донат по дуге (паттерн M)                    |
| Статистика / рост          | бары scaleY (паттерн L)                      |
| Галочка / успех / крест    | SVG-путь галочки/креста через drawPath       |

> ⚠ **Lottie в этом движке НЕ работает** (0.7.26: рендер не отрисовывает
> анимации ни через `path`, ни через `animationData` — проверено на видео 83).
> Ассеты в `assets/lottie/` оставлены на будущее; при обновлении движка
> перепроверить тестовым рендером, до этого — только SVG.

### 7.6 Переходы между сценами (v3, банк Remotion)

Сцены не встык, а с переходом — «дорогой» монтаж. Окна сцен
(`data-start`/`data-duration`) **перекрываются** на длительность перехода D
(входящая стартует за D до конца уходящей), иначе HyperFrames спрячет одну.

**Все 5 хелперов — в `shared/helpers.js`** (канон, с `kill()` и
`immediateRender:false` внутри — реализации не копировать):

| Переход   | Что делает                                       | Когда применять            |
| --------- | ------------------------------------------------ | -------------------------- |
| `crossfade(out,in,at,D=0.5)`  | наплыв + лёгкий scale            | продолжение одной мысли    |
| `push(out,in,at,D=0.55)`      | сдвиг вбок (листание)            | следующий шаг / пункт      |
| `zoomPunch(out,in,at,D=0.5)`  | удар из мелкого `back.out`       | акцент, важное число       |
| `wipe(out,in,at,D=0.6)`       | clip-path сбоку                  | контраст «было → стало»    |
| `wipeUp(out,in,at,D=0.6)`     | clip-path снизу вверх            | переход к выводу / CTA     |

Правила чередования (минимум 4 из 5 типов на ролик и т.д.) — в CLAUDE.md,
раздел «Правило переходов между сценами».

## 8. Аватар и компоновка по вертикали (v3 — КРУПНЫЙ аватар)

Аватар крупный, **слева снизу**. Кадр 1080×1920 делится так:

```
┌───────────────────────────────┐  y=0
│                               │
│      ВЕРХ — основной блок      │   ← главная масса контента
│   (заголовки, карточки, чарты) │     центрировать здесь, по ШИРИНЕ — вся
│                               │     ширина; вертикально — чуть ВЫШЕ центра
├───────────────┬───────────────┤  y=1248  (нижние 35% высоты)
│  ПУСТО         │  правый-нижний │
│  (под аватар)  │  угол — НЕ пусто:│
│  x<540, не лезть│  доп.контент в  │
│  сюда контентом│  нашем стиле    │
└───────────────┴───────────────┘  y=1920
              x=540
```

**Зона аватара (контент НЕ лезет):** левый-нижний прямоугольник —
`x < 540px AND y > 1248px` (50% ширины × 35% высоты).

**Правый-нижний угол** (`x > 540px AND y > 1248px`) — НЕ оставлять пустым:
ставить туда вторичный элемент в стиле темы (доп. подпись/стат, app-иконку,
маленький Lottie, callout, CTA-чип, декоративный коннектор). Он соседствует
с аватаром, поэтому второстепенный — не главный фокус сцены.

**Основной блок — чуть ВЫШЕ центра.** Главную массу (заголовок/карточки/чарт)
центрировать с вертикальным центром ≈ `y 760–820` (а не 960). Контент может
доходить до центра и чуть ниже, НО не залезать в левый-нижний прямоугольник аватара.

> ⚠ НЕ прижимать контент к верхней кромке (`top: 60–120px`) — это оставляет
> пустую середину и выглядит top-heavy. Именно ЦЕНТРИРОВАТЬ блок по вертикали
> так, чтобы его середина была ≈ y 760 (напр. `top: 240px; bottom: 700px;`
> + flex-column + `justify-content:center`, сохраняя гориз. выравнивание сцены).
> Контент не должен опускаться ниже y≈1240 (там зона аватара).

**В зоне аватара НИЧЕГО не рисовать.** Ни плейсхолдера, ни рамки, ни круга, ни
подписи «AVATAR» — просто пустое место (фон темы). Никакого `#avatar`-элемента
в композиции быть не должно. автор сам наложит аватар поверх при монтаже.
Задача вёрстки — лишь НЕ ставить контент в этот прямоугольник.

## 9. CSS-токены — `shared/dark-amber.css` (НЕ копировать)

Подключение из композиции:


В `<style>` композиции — только сценоспецифичные правила.
Меняешь тему → правишь ОДИН файл `shared/dark-amber.css`.

## 10. НЕ-делать

- ❌ Больше одного акцентного цвета на сцену (кроме финального rainbow).
- ❌ Статичные сцены — обязательно нужно ≥1 продолжающееся движение
  (счётчик, прогресс, подсветка по очереди, pulse glow).
- ❌ Маленькую типографику — заголовки минимум 64px, числа от 180px.
- ❌ Eyebrow без пилюли — всегда `<div class="pill">` с цветной точкой.
- ❌ SVG path без `stroke: currentColor` — линии не отрисуются.
- ❌ Круглые иконки приложений — только squircle (border-radius 18–22px).
- ❌ Контент в зоне аватара — левый-нижний прямоугольник (x<540 & y>1248).
- ❌ Пустой правый-нижний угол (x>540 & y>1248) — туда вторичный контент (§8).
- ❌ Основной блок строго по центру кадра — поднимать, центр ≈ y 760–820 (§8).
- ❌ Служебные ярлыки сцен в eyebrow-пилюле (СЦЕНА N / ХУК / CTA / СРАВНЕНИЕ / ШАГ N) — зрителю не показывать; пилюля = единый тег-рубрика или убрать (§4).
- ❌ Не использовать `position:absolute; bottom:`  на clip-элементах —
  только `top:`. HyperFrames игнорирует `bottom`.

## 11. Workflow для новых видео

**Полный операционный порядок — в CLAUDE.md проекта** (он главный:
плотность сцен, переходы, караоке, SFX, автономный режим, чистка).
Краткий каркас:

1. `./prep.sh` → `scripts/queue-add.sh` — слот очереди с транскриптом и
   заготовками из шаблонов (в корень руками ничего не копировать: `index.html`
   подставляет `queue-render.sh`).
2. Верстать в файлы слота `queue/video-NN/composition*.html`.
3. Разбить транскрипт на сцены: **≥1 сцена / 6с** (10–15 сцен на 60–90с ролик).
4. Для каждой сцены выбрать паттерн A–N из §5 (метрика разнообразия — CLAUDE.md).
5. Чередовать акценты §2; ≥1 motion-приём из §7.2 в каждой сцене
   (≥1 SVG-момент на ролик, ≤1 3D; Lottie не использовать — см. §7.2).
6. Переходы между ВСЕМИ сценами из §7.6 (мин. 4 из 5 типов, окна перекрыты на D).
7. Караоке-субтитры: `node scripts/captions-from-transcript.mjs` → вычитка →
   `buildCaptions(CAP)`. SFX: только whoosh + counter.
8. Зона аватара ПУСТАЯ (§8); правый-нижний угол — вторичный контент.
9. `npm run check` → исправить errors, прочитать warnings → `npm run render`.
10. После финала: сохранить видео и закоммитить (Post-Render Cleanup в CLAUDE.md).
