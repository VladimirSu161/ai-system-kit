# Хуки: стадия осведомлённости и усилители заголовка
Подключается на Фазе 2 (заголовок) и при написании лида.
Порядок работы с существующими правилами скилла: сначала определи СТАДИЮ осведомлённости и НАСЫЩЕННОСТЬ темы (точка входа) → потом whitelist-формулы (конструкция кандидатов) → усилители из этого файла дорабатывают кандидатов → скоринг выбирает лучший. Этот файл ДОПОЛНЯЕТ whitelist и скоринг, не заменяет их.

## 1. Стадия осведомлённости читателя (Шварц, 5 стадий)

Перед вариантами заголовка определи стадию по теме — какую часть читатель уже понимает.

1. **Не осознаёт проблему.** Заголовок называет только симптом/боль, без слов «AI», «автоматизация», «n8n». Пример: «Почему ты тратишь 3 часа в день на то, что делает один клик».
2. **Знает проблему, не знает, что есть решение.** Заголовок называет проблему + намекает на существование решения, без названия инструмента. Пример: «Есть способ перестать вручную копировать данные между таблицами».
3. **Знает, что решение — автоматизация/AI, но не знает какой инструмент.** Заголовок называет категорию и обещает выбор/сравнение. Пример: «5 no-code инструментов, которые заменят рутину SMM-щика».
4. **Знает конкретный инструмент (n8n, Make), сомневается, стоит ли/получится ли.** Заголовок бьёт по конкретному возражению или результату. Пример: «n8n не для программистов? Вот как я собрал первый сценарий за вечер».
5. **Знает всё, читал десятки статей про инструмент.** Заголовок = голый факт/новость/цифра, без разогрева. Пример: «Разбор нового узла AI Agent в n8n 1.60 — что изменилось».

Правило: если стадию определить не удалось — бери стадию 2 или 3 (это основная масса аудитории новичков в канале).

Лид (первые 40–70 слов) не должен резко перепрыгивать стадию заголовка: если заголовок стадии 2, лид не встречает читателя техническим термином из стадии 4.

## 2. Насыщенность темы (Шварц, 5 стадий sophistication)

Вторая ось, независимая от осведомлённости: сколько похожих обещаний читатель УЖЕ видел в ленте по этой теме. Определи её сразу после стадии осведомлённости и тоже зафиксируй одной строкой.

1. **Тема свежая, таких обещаний в ленте почти нет** → прямое простое обещание результата, без усложнений.
2. **Обещание встречается, но не затёрто** → усилить обещание конкретикой: цифра, срок, масштаб.
3. **Лента забита такими обещаниями** («автоматизируй всё за вечер», «нейросеть сделает за тебя») → НЕ усиливать обещание, оно уже не читается. Смещай заголовок на МЕХАНИЗМ — как именно / за счёт чего работает. Пример: не «автоматизируй отчёты с ИИ», а «отчёты собирает один узел HTTP Request: связка n8n + нейросеть без кода».
4. **И механизмы примелькались** → детализируй механизм: чем легче, быстрее, надёжнее старого способа, какое известное ограничение снимает.
5. **Читатель не верит никаким обещаниям по теме** → заголовок через идентификацию, не через выгоду: читатель узнаёт в заголовке себя и свою ситуацию. Пример: «Пробовал n8n, застрял на первом же webhook и бросил? Разбор, где ломаются новички».

Быстрая проверка: мысленно поставь заголовок в ленту между пятью чужими на ту же тему. Если он отличается от них только громкостью обещания — сдвинься на шаг ниже по списку (конкретика → механизм → детализация → идентификация). Для перегретых AI-тем рабочая зона обычно стадии 3-4.

## 3. Правило цепочки

Заголовок продаёт первое предложение. Первое предложение продаёт второе. Второе — третье. И так до конца лида (Шварц).

Применение к лиду статьи:
- Каждое предложение лида обрывай на незавершённой мысли или вопросе, который закрывается только следующим предложением.
- Не давай в первом предложении лида ничего, прочитав что читатель может «удовлетвориться» и уйти (весь факт, весь вывод, всю цифру сразу).
- Проверка: закрой всё, кроме первого предложения лида — оно должно вызывать желание прочитать второе, а не ощущение законченности.

## 4. Усилители заголовка — 14 техник вербализации (Шварц, адаптация под инфостатьи)

Отброшены рекламные техники (цена, «только здесь», обвинение клейма в лжи) и техники, дублирующие уже готовые формулы скилла (вопрос, как-заголовок, личный опыт, трансформация/до-после).

1. **Квантификация** — назови число вместо общего слова. Шаблон: [абстракция] → [цифра]. Пример: «настроить автоматизацию» → «3 рабочих агента n8n за один вечер».
2. **Срок/скорость** — привяжи результат к конкретному времени. Шаблон: [результат] → [результат] + [срок]. Пример: «Настрой первый workflow за 15 минут».
3. **Сравнение** — сопоставь с привычной альтернативой. Пример: «Быстрее, чем нанимать фрилансера: собрать Telegram-бота на n8n».
4. **Метафора** — замени абстрактный инструмент образом. Пример: «n8n — конструктор Lego для твоих бизнес-процессов».
5. **Демонстрация на примере** — покажи результат через один конкретный кейс, не через общее заявление. Пример: «Как один email-маркетолог автоматизировал всю воронку без единой строчки кода».
6. **Парадокс** — переверни ожидаемую причинно-следственную связь. Пример: «Меньше кода — больше автоматизации».
7. **Снятие ограничений** — назови барьер, которого не будет. Шаблон: [результат] без [привычной сложности]. Пример: «Автоматизация без программирования и без платных API».
8. **Авторитет/инсайдер** — сошлись на источник с весом. Пример: «Разработчик n8n объясняет, как выбрать между Zapier и Make».
9. **Новизна** — подчеркни, что это про свежую версию/функцию. Пример: «Новый узел AI Agent в n8n: что изменилось с версии 1.5».
10. **Слом ожидаемого механизма** — удиви тем, что привычный шаг не нужен. Пример: «Забудь про API-документацию — вот как подключить нейросеть без кода».
11. **Название проблемы** — дай безымянной боли ярлык, чтобы читатель узнал себя. Пример: «Синдром 100 вкладок: как автоматизация убирает хаос в работе».
12. **Предупреждение о ловушке** — предупреди о частой ошибке до того, как её показать. Пример: «Не подключай ChatGPT к n8n, пока не прочитаешь это».
13. **Констатация разницы** — прямо назови, чем отличается от того, что читатель уже пробовал. Пример: «Чем n8n на самом деле отличается от Zapier».
14. **Оспаривание ограничивающего убеждения** — назови мысль читателя и опровергни её в заголовке. Пример: «Ты не опоздал: разбираться в AI-автоматизации можно начать и без опыта».

## 5. Из Copyblogger (не пересекается с существующим)

**Размер обещания в заголовке = ширина аудитории.** Чем технологичнее термин в заголовке (n8n, webhook, JSON, API) — тем уже и опытнее аудитория, которую он привлечёт; формулировка через голую боль без терминов — тем шире охват, но ниже релевантность клика.
- Для широкого охвата: обещание через боль/результат, без названия инструмента в заголовке.
- Для отсева случайных кликов и удержания дочитывания: осознанно оставь один технический термин как фильтр.

**Три оси вариантов заголовка** — при генерации 8–12 кандидатов дели их не только по формулам, но и по оси боль / выгода / возражение, чтобы кандидаты не были вариациями одной и той же мысли:
- Ось боли: «Почему твой n8n-workflow ломается на третьем шаге».
- Ось выгоды: «Как n8n возвращает тебе 10 часов в неделю».
- Ось возражения: «"Это слишком сложно для новичка" — неправда, вот пример».
