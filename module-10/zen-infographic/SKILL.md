# Zen Infographic Generator

Скилл строит **3 минималистичные инфографики** под одну статью Дзена. Логика — HTML+CSS шаблон в стиле канала → Puppeteer рендерит каждый блок `.infographic` в PNG. Никакой генерации изображений, всё кастомное и предсказуемое.

---

## Когда использовать

**Автоматически** — на Phase 7 пайплайна `articles-v2`, сразу после Phase 6 (промпты для обложек). Главный скилл передаёт путь к сохранённой статье, и `zen-infographic` дочитывает её и рендерит.

**Вручную** — когда есть готовая статья и нужно добавить визуалы:
- «сделай инфографики для статьи [путь]»
- «нужны 3 визуала для последней статьи»
- «добавь иллюстрации к статье про X»

В обоих случаях входной артефакт — путь к `.md` файлу статьи в Obsidian vault.

---

## Куда сохраняются файлы (ВАЖНО)

Инфографика **НЕ** кладётся рядом со статьёй в Obsidian. Все картинки и HTML-исходники складываются в общую папку на рабочем столе — чтобы автору было удобно грузить их в редактор Дзена, не закапываясь в недра vault.

**Базовая папка вывода:**
```
~/Desktop/zen-infographics/infographics-{slug}/
```
- `{slug}` — то же короткое имя статьи, что и раньше (например, для статьи `ai-agent-analyst` папка будет `infographics-ai-agent-analyst/`).
- Папку `infographics-{slug}/` нужно создать (`mkdir -p`), если её ещё нет.
- В неё кладутся `infographic-1.png`, `-2.png`, `-3.png` и `infographics.html`.
- Сам текст статьи (`.md`) остаётся в Obsidian — туда пишутся только текстовые маркеры `[картинка 1..3]` и таблица-легенда (см. Фазу 5).

## Размер и формат

- **1280×720** (16:9, горизонтальный) — формат под Дзен
- PNG, прозрачный фон отключён (фон бежевый из палитры)
- 3 файла в папке на рабочем столе `~/Desktop/zen-infographics/infographics-{slug}/`:
  - `infographic-1.png`
  - `infographic-2.png`
  - `infographic-3.png`
- Рядом сохраняется `infographics.html` (исходник, чтобы быстро поправить и перерендерить)

## Палитра и стиль (зафиксировано, не варьируется)

Те же дизайн-токены, что в `instagram-carousel-creator`, чтобы держать единый бренд канала через все платформы.

| Токен | Hex | Смысл |
|---|---|---|
| `--bg` | `#FAFAF7` | Тёплый off-white фон |
| `--ink` | `#111111` | Основной текст и цифры |
| `--ink-soft` | `#4A4A48` | Подписи, источники, второстепенное |
| `--rail` | `#E5E5E0` | Тонкие линии, разделители, оси графиков |
| `--peach` | `#E89B7B` | Акцент 1 (риск / контраст / boost) |
| `--sage` | `#8FA68E` | Акцент 2 (рост / решение / позитив) |

**Шрифт:** Onest (Google Fonts), веса 400/500/700/800.

**Жёсткие правила, чтобы не получился AI-ный визуал:**
- Один акцентный цвет на инфографику (peach ИЛИ sage, не оба сразу)
- Никаких градиентов, теней, glow-эффектов
- Никаких эмодзи в инфографике
- Никаких 3D-объектов и скевоморфизма
- Никаких неона, никакого dark mode
- Минимум 60% воздуха в кадре
- Один главный смысл на инфографику (одна цифра, или одно сравнение, или одна таблица)
- Источник данных мелким шрифтом внизу, серым (`--ink-soft`)

## 3 паттерна инфографик (выбирай 3 разных)

Скилл сам подбирает 3 паттерна под содержимое статьи. Главное правило — все три должны быть **разные** (не три цифры подряд, не три графика подряд).

### P1. Big number (одна цифра-крючок)
Когда: в статье есть одна сильная цифра (зарплатный разрыв, рост в X раз, % премиума).
Структура: огромная цифра по центру + одна короткая подпись над/под ней + источник.

### P2. Comparison (A vs B)
Когда: контраст «с AI / без AI», «было / стало», «зарплата у тех / зарплата у других».
Структура: два блока рядом, разделитель `vs` или вертикальная линия, итоговая стрелка с дельтой.

### P3. Bar chart (рост по категориям)
Когда: список с числами, рейтинг отраслей, рост вакансий по нишам.
Структура: 4-6 горизонтальных столбиков, ось внизу, акцентом подсвечен 1 главный.

### P4. Quote card (цитата-инсайт)
Когда: есть сильная мысль или тезис, который хочется выделить.
Структура: короткая фраза 6-12 слов крупно + атрибуция мелко.

### P5. Mini table (3-4 строки)
Когда: уплотнённая таблица, которая в markdown в Дзене выглядит блёкло.
Структура: 3-4 строки × 2-3 колонки, акцентом выделена 1 строка (главный insight).

### P6. Process / steps (3-4 шага)
Когда: пайплайн, цепочка действий, «как это устроено».
Структура: 3-4 блока в ряд, тонкие стрелки между ними, подпись под каждым.

**Логика выбора:** скилл читает статью, находит 3 самых сильных смысловых ставки, под каждую подбирает наиболее точный паттерн. Не должно быть двух одинаковых.

## Pipeline

### Фаза 1 — Чтение статьи

Прочти `.md` файл по переданному пути. Извлеки:
- Заголовок (для title HTML файла)
- Slug темы (из YAML или имени файла)
- Все цифры, проценты, конкретные кейсы
- Главные контрасты (X vs Y)
- Возможные цитаты-инсайты

### Фаза 2 — Выбор 3 идей и их расстановка

**Шаг 2.1 — Кандидаты.** Сформируй список из 5-7 кандидатов на инфографику, оцени по силе:
- Цифра должна быть конкретной (не «вырос», а «+34%»)
- Контраст должен быть наглядным
- Должен быть источник (иначе цифра «голая»)

Выбери **топ-3**. Распредели по разным паттернам (никаких двух P1 подряд).

**Шаг 2.2 — Расстановка по статье (важно).**

В Дзене у статьи уже есть **обложка** в самом начале, она работает как первая визуальная остановка. Поэтому начало статьи (первые ~25% текста) визуально насыщено и в иллюстрациях не нуждается — читатель ещё не устал. После трёх инфографик подряд в первой половине остаётся «полотно» в финале, которое плохо дочитывается.

**Правило равномерности:** обложка + 3 инфографики = 4 визуальные опоры. Распредели их так, чтобы дистанция между опорами была примерно равной, а инфографики **сдвинуты ближе к концу**.

Грубая карта зон (в долях от длины тела статьи между лидом и финалом):
- **Обложка** — 0% (дана)
- **Инфографика 1** — около 35-45% длины (примерно середина первой половины основных H2)
- **Инфографика 2** — около 60-70% длины
- **Инфографика 3** — около 80-90% длины (перед финалом / FAQ, чтобы разбить «полотно»)

**Приоритеты при выборе места (строго в этом порядке):**

1. **Тематическая уместность — главное.** Инфографика всегда встаёт сразу после H2, к которой она реально привязана содержанием. Цифра в инфографике должна быть та же, что обсуждается в этом разделе текста.
2. **Сила факта.** Из равных по уместности мест выбирай тот, где факт сильнее (конкретнее, с источником, нагляднее контраст).
3. **Равномерность — как тай-брейкер.** Если у инфографики есть несколько одинаково валидных по тематике мест — выбирай то, которое лучше попадает в зоны 35-45% / 60-70% / 80-90%. Если все три кандидата сильны и распределены по статье — отлично. Если все цифры объективно сосредоточены в начале статьи, не вытягивай искусственно слабый факт в конец только ради сетки.

**Запреты (даже если сильный факт находится там):**
- Не ставить инфографику до первой H2 (там работает обложка и лид, читатель ещё не устал)
- Не ставить две инфографики подряд внутри одной H2-секции

**Желательно, но не любой ценой:**
- Не оставлять весь финал статьи (последние 2+ H2) без визуала. Если инфографика-3 тематически тянется к началу, попробуй найти альтернативную привязку ближе к концу — но только если она не натянута.

### Фаза 3 — Верстка HTML

Создай папку вывода и скопируй туда шаблон:
```bash
mkdir -p ~/Desktop/zen-infographics/infographics-{slug}
cp ~/.claude/skills/zen-infographic/assets/template.html ~/Desktop/zen-infographics/infographics-{slug}/infographics.html
```
Затем в `~/Desktop/zen-infographics/infographics-{slug}/infographics.html` подставь:
- 3 блока `.infographic` с нужными паттернами
- Контент из статьи (цифры, подписи, источники)
- Чередуй акценты peach / sage (например, 1=sage, 2=peach, 3=sage)

В шаблоне уже есть все CSS-классы под паттерны P1-P6.

### Фаза 4 — Рендер

Запусти `node ~/.claude/skills/zen-infographic/scripts/render.js ~/Desktop/zen-infographics/infographics-{slug}/infographics.html`. PNG сохранятся рядом с HTML — то есть в той же папке на десктопе.

Скрипт:
- Запускает Puppeteer (если не установлен — сам ставит в папку скилла)
- Открывает HTML
- Делает screenshot каждого `.infographic` отдельно
- Сохраняет как `infographic-1.png`, `infographic-2.png`, `infographic-3.png`

### Фаза 5 — Допись в файл статьи

Два действия: (1) расставить маркеры **прямо в тексте** статьи и (2) добавить таблицу-легенду в конец файла.

**Шаг 5.1 — Маркеры в теле статьи (главное).**

В каждое из трёх выбранных мест (из Фазы 2) вставь текстовый маркер **отдельной строкой** (пустая строка до и после), ровно в таком виде:

```markdown
[картинка 1]
```

Так для всех трёх: `[картинка 1]`, `[картинка 2]`, `[картинка 3]`. Нумерация маркеров совпадает с номерами PNG-файлов (`[картинка 1]` → `infographic-1.png`).

Зачем именно так: автор копирует весь текст статьи из Obsidian и вставляет в редактор Дзена одним куском. Локальные PNG при этом НЕ переносятся (редактор Дзена не видит диск), картинки он загружает вручную по одной. Маркер `[картинка 1]` в потоке текста — это видимая подсказка «вот сюда залить первую инфографику». Поэтому маркер должен быть:
- **простым текстом в квадратных скобках**, без markdown-разметки картинки (`![]()` или `![[]]` Дзен покажет как мусор);
- **на отдельной строке** — так он не прилипнет к абзацу и его легко найти глазами и удалить после загрузки картинки;
- встроен ровно в то место, что выбрано в Фазе 2 (сразу после нужной H2-секции / после таблицы), не «примерно рядом».

Это не нарушает запрет родительского скилла на «картинки в тексте» — там запрещены реальные эмбеды изображений, а это текстовый плейсхолдер, который пользователь сам заменит на загруженную картинку.

**Шаг 5.2 — Таблица-легенда в конец файла.**

В конец `.md` файла статьи (после блока обложек) добавь блок — он связывает номер маркера с файлом и паттерном:

```markdown
---

## Инфографики для тела статьи (3 шт.)

Маркеры `[картинка 1]`, `[картинка 2]`, `[картинка 3]` уже расставлены в тексте выше. При переносе в Дзен на каждом маркере загрузи соответствующий PNG из папки `~/Desktop/zen-infographics/infographics-{slug}/` и удали строку с маркером.

| Маркер | Паттерн | Стоит после | Файл |
|---|---|---|---|
| `[картинка 1]` | [P-номер название] | [H2 «...» / таблицы] | `infographic-1.png` |
| `[картинка 2]` | [P-номер название] | [H2 «...»] | `infographic-2.png` |
| `[картинка 3]` | [P-номер название] | [H2 «...»] | `infographic-3.png` |

HTML-исходник: `~/Desktop/zen-infographics/infographics-{slug}/infographics.html` (правь и перерендеривай через `node ~/.claude/skills/zen-infographic/scripts/render.js ~/Desktop/zen-infographics/infographics-{slug}/infographics.html`).
```

### Фаза 6 — Отчёт в чат

В чат:
- Путь к папке с PNG на рабочем столе (`~/Desktop/zen-infographics/infographics-{slug}/`)
- Список из 3 паттернов + рекомендованное место вставки в статье
- Команда перерендера если захочется править

НЕ дублировать HTML, не дублировать сам контент.

## Интеграция в articles-v2

Добавляется как **Phase 7** в конец пайплайна (после Phase 6 — обложек).

В `SKILL.md` родителя добавляется блок:
```
### Фаза 7 — Инфографики для тела статьи

После Phase 6 вызови `Skill('zen-infographic')` с путём к сохранённой статье.
Скилл прочитает её, отрендерит 3 PNG в папку ~/Desktop/zen-infographics/, расставит маркеры
`[картинка 1..3]` прямо в тексте статьи и допишет таблицу-легенду в конец
файла. Если статья короткая и без цифр - можно пропустить.
```

Триггер автозапуска: если в статье **есть минимум 3 конкретные цифры или контраста**. Если нет — пропускаем, в чат отчёт «инфографики не нужны: в статье недостаточно числовых данных».

## Self-check перед выдачей

1. Все 3 PNG созданы и размером ~1280×720
2. Используется только палитра шаблона (peach, sage, ink, bg — замени на свою в template.html)
3. На каждой инфографике только ОДИН акцентный цвет
4. Все 3 инфографики используют РАЗНЫЕ паттерны (P1-P6)
5. На каждой есть источник данных (мелким, серым)
6. Нет эмодзи, нет градиентов, нет теней, нет 3D
7. Есть минимум 60% воздуха в каждом кадре
8. Маркеры `[картинка 1]`/`[картинка 2]`/`[картинка 3]` вставлены в тело статьи (каждый отдельной строкой, на месте из Фазы 2), плюс таблица-легенда дописана в конец файла
9. HTML-исходник сохранён рядом для будущих правок
10. В чат — только путь + список паттернов, без дублирования контента
11. **Расстановка:** каждая инфографика стоит после тематически релевантной H2 (главное). До первой H2 — нет, две подряд в одной секции — нет. При прочих равных — распределены по зонам ~35-45% / ~60-70% / ~80-90%, но равномерность не вытягивается за счёт натянутой привязки.
