# SETUP — развёртывание конвейера reelcraft

## Инструкция для агента

Ты — Claude Code (или другой кодовый агент) на машине ученика. Твоя задача:
довести этот репозиторий до состояния «человек записал голос — на выходе
готовый вертикальный ролик с караоке, скринкастами, звуком и музыкой».

Правила работы на всю установку:

- Веди человека по шагам, по-русски, простым языком. Он может быть новичком
  в терминале: объясняй, что делает команда, до того как её запустить.
- Не пропускай проверки в конце шагов. Шаг не прошёл проверку — чини его,
  а не иди дальше.
- Ничего не удаляй за пределами папки проекта. Скачивания больше 100 МБ
  (модель распознавания речи, зависимости, headless-браузер) — предупреждай
  заранее: сколько весит и сколько примерно ждать.
- Личные данные (шаг 6) спроси у человека одним блоком вопросов, не по одному.
- В конце установки покажи короткий отчёт: что установлено, что осталось
  сделать руками, какая первая команда для первого ролика.

Полная установка занимает 30–60 минут, из них большая часть — скачивания.

## Шаг 0. Что это за конвейер (расскажи человеку своими словами)

На вход — запись голоса (или видео, из которого нужен только звук). Дальше:

1. `prep.sh` нормализует громкость до −14 LUFS и ускоряет речь ×1.2.
2. `queue-add.sh` распознаёт речь пословно (whisper.cpp) и заводит «слот»
   ролика: звук, транскрипт, заготовка субтитров.
3. Агент читает транскрипт, режет его на смысловые биты и пишет **сториборд** —
   постановку по каталогу 152 приёмов video-shotcraft.
4. Агент верстает сцены на Remotion (React-код), прогоняет линт и авто-QA.
5. Рендер → мастеринг звука → готовый MP4 1080×1920.

Правила, по которым всё это собирается (темп, композиция, звук, QA), лежат
в `CLAUDE.md` — его агент читает первым шагом каждой сборки ролика.

**Про лицензию Remotion:** для одного человека и небольших команд — бесплатно
(Remotion Free License), включая монетизацию роликов. Компаниям от 4 человек
нужна платная лицензия. Скажи об этом человеку прямо, детали —
`library/remotion-ecosystem.md`.

## Шаг 1. Проверить систему

Конвейер разрабатывался на macOS. На Linux работает всё, кроме `--voice`
(забор записей из Диктофона macOS) и `caffeinate` (не давать машине уснуть) —
их пропусти. Windows — только через WSL.

Проверь, что стоит, одной командой:

```bash
node -v; npm -v; ffmpeg -version | head -1; python3 -V; git --version
```

Нужно: **Node.js 20+**, **ffmpeg**, **Python 3**, **git**.

Чего нет — доставь (macOS, через Homebrew):

```bash
brew install node ffmpeg git
```

Питоновская библиотека PIL нужна для авто-QA (склейка контактного листа):

```bash
python3 -c "import PIL; print('PIL ok')" || python3 -m pip install --user Pillow
```

Проверка шага: все пять команд отвечают версиями, `PIL ok` печатается.

## Шаг 2. Распознавание речи (whisper.cpp + модель)

```bash
brew install whisper-cpp        # даёт команду whisper-cli
```

Модель — `large-v3-turbo`, **1.5 ГБ**, качается один раз. Предупреди человека
про объём и спроси, куда её класть (по умолчанию — `~/.cache/whisper-models`):

```bash
mkdir -p ~/.cache/whisper-models
curl -L --progress-bar \
  -o ~/.cache/whisper-models/ggml-large-v3-turbo.bin \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin
```

Если человек хочет полегче — `ggml-small.bin` (465 МБ, та же ссылка с другим
именем файла), но на терминах он ошибается заметно чаще.

Скрипты ищут модели в `$WHISPER_MODELS_DIR`, по умолчанию —
`~/.cache/whisper-models`. Нестандартная папка → пропиши в профиль оболочки:

```bash
echo 'export WHISPER_MODELS_DIR="/свой/путь"' >> ~/.zshrc
```

Проверка шага:

```bash
whisper-cli --help | head -3
ls -lh ~/.cache/whisper-models/
```

## Шаг 3. Каталог приёмов video-shotcraft

Это отдельный открытый проект (Apache-2.0): 152 карточки приёмов с готовыми
demo-компонентами. Конвейер ссылается на него из `library/index-*.md`, и
оттуда же берутся звуковые эффекты. **Клонировать нужно рядом с проектом**,
на один уровень выше:

```bash
git clone https://github.com/Vincentwei1021/video-shotcraft ../video-shotcraft
```

Проверка шага (должны существовать):

```bash
ls ../video-shotcraft/skill/references/shots/ | head
ls ../video-shotcraft/skill/demos/ | head
```

Если человек уже держит этот репозиторий в другом месте — не клонируй второй
раз, а поправь пути: в `library/INDEX.md`, `library/index-*.md`,
`library/components.md`, `library/energy-arc.md` относительный путь
`../video-shotcraft/` замени на фактический.

## Шаг 4. Зависимости движка

```bash
cd engine && npm install && cd ..
```

Ставится Remotion 4.0.520 и React 19 — около 500 МБ в `engine/node_modules/`.
Первый рендер дополнительно докачает headless-браузер (~93 МБ) — это норма,
прерывать нельзя.

Проверка шага:

```bash
cd engine && npx tsc --noEmit && cd ..
```

Ошибок типов быть не должно.

## Шаг 5. Звуковые банки

В репозитории лежат описи банков, но не сами аудиофайлы: эффекты честнее
брать из первоисточника (shotcraft, Apache-2.0), а музыка Mixkit по лицензии
не перевыкладывается отдельными файлами. Скрипт доложит их на место:

```bash
scripts/setup-assets.sh
```

Он скопирует 106 звуковых эффектов из клона shotcraft и подскажет, что делать
с музыкой. **Музыку человек скачивает сам** — 4–5 бесплатных треков с
mixkit.co (характеры и названия тех, на которых собран конвейер, —
в `engine/public/shared/bgm/INDEX.md`), кладёт в `engine/public/shared/bgm/`
и дописывает строкой в INDEX. Без 4–5 треков не работает правило анти-повтора:
соседние ролики не должны идти под одну музыку.

Проверка шага:

```bash
find engine/public/shared/sfx -name '*.mp3' | wc -l   # ожидается 106
find engine/public/shared/bgm -name '*.mp3' | wc -l   # ожидается 4-5
```

## Шаг 6. Константы канала (данные от человека)

Спроси у человека **одним блоком**:

1. **Хендл канала** — как подписывать финальную карточку (например `@my_channel`).
2. **Слоган** — строка под хендлом, 3–5 слов: о чём канал.
3. **Скрин канала** — путь к картинке с шапкой канала (видно название и число
   подписчиков). Нужен как «пруф» в финале. Нет скрина — пусть сделает сейчас.
4. **Число подписчиков** строкой — например «1 200 подписчиков». Число берётся
   настоящее, выдумывать нельзя (правило 17).
5. **Куда складывать готовые ролики** — папка, например `~/Desktop/Ролики`.
6. **Язык записи** — русский по умолчанию; другой → значение для `WHISPER_LANG`.

Дальше сделай сам:

- Впиши ответы в `engine/src/channel.ts` (файл уже размечен комментариями).
- Положи скрин канала в `engine/public/shared/cta/tg-channel.jpg`, заменив
  заглушку. Померь его пропорции и пропиши `ctaProofAspect` (высота/ширина)
  — иначе картинка в карточке растянется.
- Создай папку вывода, если её нет.
- Не русская речь → допиши `WHISPER_LANG` в профиль оболочки.

Проверка шага: в `engine/src/channel.ts` не осталось значений-заглушек
(`@your_channel`, «О чём твой канал»).

## Шаг 7. Персонаж светлой темы

Тема по умолчанию — «Sticker Light»: светлый кадр, снизу стоит нарисованный
персонаж и «играет» позами под речь. В репозитории лежат **серые
силуэты-заглушки** — движок с ними запускается, но в ролик такое не выпустишь.

Спроси человека, как он хочет:

**(а) Сделать своего персонажа** — основной путь. Нужно 10 файлов PNG
**с прозрачным фоном**, один персонаж в одном стиле, разные позы, имена ровно
такие (движок ищет по ним):

```
pose-base.png  pose-welcome.png  pose-wave.png  pose-present-left.png
pose-present-right.png  pose-think-chin.png  pose-think-cross.png
pose-shrug.png  pose-stop.png  pose-fists.png
```

Требования: одинаковый рост фигуры на всех позах (иначе персонаж «прыгает»
при смене), фигура по центру, размер около 1056×1140, без теней на фоне.
Что означает каждая поза — в `engine/public/shared/character/README.md`.

Как получить: сгенерировать в любой рисующей нейросети по одному описанию,
меняя только позу и руки, потом убрать фон. Формулировка для генерации:
«персонаж в плоском рисованном стиле, ровный контур, спокойные цвета,
прозрачный фон, фигура целиком, поза: <нужная>». Готовые файлы положить в
`engine/public/shared/character/` поверх заглушек.

**Обязательно посмотри готовые позы глазами** — лишние руки и обрезанные
кисти генерация выдаёт регулярно, а в кадре это сразу заметно.

**(б) Работать без персонажа** — тогда основная тема тёмная (`noir`),
её правила в `library/adaptive-theme.md`, а `light` не используется.
Заглушки при этом можно оставить как есть, они ни на что не влияют.

Стикеры (`engine/public/shared/stickers/`, 6 штук) — рабочие, не заглушки:
можно пользоваться, можно заменить своими, можно не использовать.

Проверка шага: открой любой файл `pose-*.png` и убедись глазами, что это
твой персонаж, фон прозрачный, фигура не обрезана.

## Шаг 8. Установить скилл

Скилл — это инструкция агенту «как собирать ролик от начала до конца».
Положи его на место и подставь в него реальный путь к проекту:

```bash
mkdir -p ~/.claude/skills/reelcraft
cp SKILL.md ~/.claude/skills/reelcraft/SKILL.md
```

Затем открой `~/.claude/skills/reelcraft/SKILL.md` и в строке про путь к
проекту укажи фактический абсолютный путь этой папки (`pwd` покажет его).

Проверка шага: в новой сессии Claude Code скилл `reelcraft` виден в списке
`/skills`.

## Шаг 9. Контрольный прогон

Проверяем, что движок живой, ещё до первого настоящего ролика.

Studio (интерактивный просмотр композиций в браузере):

```bash
cd engine && npm run dev
```

Должны открыться композиции `DemoLight`, `DemoNoir`, `DemoFlow`. Посмотри
`DemoLight` глазами: светлый фон, карточка, персонаж снизу, субтитры внизу.
Закрой Studio (Ctrl+C).

Тестовый рендер (первый раз докачивает браузер ~93 МБ, это норма):

```bash
cd engine && npx remotion render src/index.ts DemoLight out/demo.mp4
```

Проверка шага: файл `engine/out/demo.mp4` существует, открывается, длится
10 секунд, вертикальный.

Линт сцен (на demo он ничего не найдёт — важно, что сам запускается):

```bash
node scripts/lint-scenes.mjs demo || true
```

## Шаг 10. Первый ролик

Объясни человеку порядок и запусти вместе с ним:

1. Он записывает голос 40–60 секунд на любую тему, где есть что показать на
   экране (какой-то сервис, репозиторий, своя папка проекта). Файл кладёт
   в `inbox/`.
2. `./prep.sh` — обработка звука.
3. `scripts/queue-add.sh inbox/<имя>-prep.mp4 01` — слот с номером 01.
4. Дальше говорит агенту: **«Собери ролик 01 через reelcraft»** — и агент
   работает по скиллу: вычитывает транскрипт, пишет сториборд, верстает
   сцены, гоняет QA, рендерит.

Что ещё понадобится по ходу первого ролика — предупреди заранее:

- **Живой экран обязателен** (правило 27): в ролике должен быть хотя бы один
  настоящий скриншот или запись экрана с наездом камеры. Пусть человек заранее
  снимет то, о чём говорит, и положит в `inbox/screenshots/` или
  `footage/clips/` (плюс строка в `footage/catalog.md`).
- **Иконки брендов**, которые звучат в речи, докачиваются командой
  `node scripts/fetch-icons.mjs <названия>` — агент сделает это сам.

## Что НЕ входит в этот комплект и почему

| Чего нет | Почему | Что делать |
|---|---|---|
| Звуковые эффекты (106 mp3) | Подмножество библиотеки video-shotcraft (Apache-2.0) — берём из первоисточника | шаг 5, `scripts/setup-assets.sh` |
| Музыка (BGM) | Треки Mixkit: использовать в роликах можно, перевыкладывать файлами — нет | шаг 5, скачать с mixkit.co |
| Модель распознавания речи | 1.5 ГБ, качается отдельно | шаг 2 |
| Каталог 152 приёмов (карточки и demo) | Отдельный открытый репозиторий | шаг 3, `git clone` |
| Готовые ролики автора | Личный контент и голос | не нужны: образец кода — `engine/src/videos/demo/` |
| Lottie-анимации (кроме одной) | Частые наборы разрешают использовать анимации, но запрещают перевыкладывать файлы | банк пополняется самостоятельно, порядок — `lottie/INDEX.md` |
| Персонаж светлой темы | В репозитории только силуэты-заглушки | шаг 7, сделать своего |
| Банк живого футажа | Личные записи экрана | свой банк собирается в `footage/` |

Что входит и работает сразу: движок Remotion с общими компонентами и двумя
темами, все правила конвейера (`CLAUDE.md`), скилл, скрипты обработки звука
и QA, конспект каталога приёмов (`library/index-*.md`), шрифты, 2000 иконок
Lucide и 67 иконок брендов, стикеры. Происхождение и лицензия каждого
материала — в `LICENSES.md`, полные тексты лицензий — в `licenses/`.

## Если что-то пошло не так

| Симптом | Причина и лечение |
|---|---|
| `✗ Нет модели whisper` | Модель не там, где ищет скрипт → задай `WHISPER_MODELS_DIR` (шаг 2) |
| `✗ Нет whisper-cli` | `brew install whisper-cpp` |
| Рендер «висит» на первом запуске | Докачивается headless-браузер ~93 МБ — дать доработать |
| Шрифты не грузятся / рендер падает по таймауту | Шрифты только локальные; `@remotion/google-fonts` в этом проекте запрещён |
| Линт ругается на `Math.random` / `Date.now` | Рендер многопоточный: случайность только через `mulberry32` из `src/lib/helpers.ts` |
| Субтитры налезают на картинку | Караоке-полоса темы неприкосновенна: light 880–1030, тёмные 1450–1620 |
| Персонаж «двоится» при смене поз | `<Character swapMode="dip">` — не `fade` |
| Картинка в наезде уезжает вправо и вверх | У `PageCam` в вертикали задавать явно `viewportW={1080} viewportH={1920}` |
| Пустой низ кадра, «дырка» под контентом | Правило 20: контент до ~1400 или персонаж закрывает низ |

Все команды и правила, которые понадобятся дальше, — в `CLAUDE.md`
(нормы) и `SKILL.md` (порядок сборки ролика).
