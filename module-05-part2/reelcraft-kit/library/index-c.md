# Инвентаризация video-shotcraft: transition + effects (пакет C)

Контекст оценки: вертикальный 1080×1920 говорящий ролик 40–90 сек, переходы должны укладываться в 0.4–0.8с на границах фраз, внизу полоса караоке-субтитров (y 880–1030), в теме с персонажем переход не должен трогать персонажа — только info-zone (y 110–870). Все карточки в исходниках считаны под ландшафт 1920×1080 — этот пересчёт координат отдельно не повторяется в каждой записи, если не даёт дополнительной специфики.

---

## Переходы (transition/, 19 карточек)

### bottom-push-stack-wipe · transition
- Суть: новый раздел цельным цветным экраном въезжает снизу и физически выталкивает старый экран вверх — эффект «продавленной кассы».
- Триггеры: переход между мыслями / связка-объединение (смена главы)
- Энергия: средняя · Длительность: ~1с на присдвиг (+ hold ~1.2с)
- Вертикаль: с адаптацией (пересчёт координат под 1080×1920 тривиален — это заливка на весь кадр)
- Зона: весь кадр — требует, чтобы всё физически «выехало», ограничить только info-zone нельзя без потери эффекта выталкивания. Для темы с персонажем не годится.
- Звук: не указан явно, просится глухой удар в момент присдвига
- Грабли: <20 кадров = «мигание» вместо перехода; смена направления присдвига посреди ролика рушит ощущение «хребта»; между секциями нужен hold ≥1.2с.
- Demo: ../video-shotcraft/skill/demos/transition/bottom-push-stack-wipe/BottomPushStackWipe.tsx

### bubble-swarm-takeover · transition
- Суть: рой перламутровых пузырей ~2с наплывает и застилает экран, в пике прячется жёсткая склейка сцен, затем пузыри расходятся.
- Триггеры: переход между мыслями / связка-объединение; вариант с i18n-капсулами — перечисление функций
- Энергия: средняя-высокая (устойчивое кипение без резкого удара) · Длительность: ~4.3с
- Вертикаль: с адаптацией (пересчёт под 1080×1920, пузыри масштабируются по площади)
- Зона: весь кадр — пик требует полного перекрытия экрана, иначе видны щели старой сцены. Не годится для темы с персонажем.
- Звук: не указан явно, длинная фаза наплыва — кандидат под нарастающий свист/вуш
- Грабли: 6 крупных пузырей по сетке — обязательный «страховочный» слой, без него в пике остаются щели; 3 слоя глубины нужны для объёма, иначе плоские наклейки.
- Demo: ../video-shotcraft/skill/demos/transition/bubble-swarm-takeover/BubbleSwarmTakeover.tsx

### card-flip-reveal · transition
- Суть: UI-карточка переворачивается на 180° по Y — лицевая сторона (интерфейс) сменяется тыльной с крупным числом-результатом.
- Триггеры: результат-финал / было→стало (функция → её показатель)
- Энергия: средняя-высокая · Длительность: ~0.9с один переворот (серия из 3 карт ~4.9с с hold)
- Вертикаль: с адаптацией (пересчёт координат, сама карточка компактна и легко ставится в info-zone)
- Зона: применим только к info-zone — это локальный элемент (одна карточка), персонаж не задет
- Звук: лёгкое «пак» на каждом останове переворота (кандидат sound-design §4.5)
- Грабли: перевёрнутая сторона обязана быть смысловой парой (функция→результат), иначе переворот — просто украшение; путать с wall-reveal (та переворачивает для входа, эта — для раскрытия).
- Demo: ../video-shotcraft/skill/demos/transition/card-flip-reveal/CardFlipReveal.tsx

### card-flock-tumble · transition
- Суть: три экрана-карточки 3D-облетают и встают лесенкой, затем стягиваются в точку и взрываются дымным кольцом с крупным слоганом — пик энергии всего пакета.
- Триггеры: результат-финал / CTA (кульминация раздела перед лозунгом)
- Энергия: очень высокая · Длительность: ~4.5с
- Вертикаль: с адаптацией (сложная 3D-сцена, нужен полный пересчёт масштабов)
- Зона: весь кадр — карты, дым и текст занимают всё пространство. Не годится для темы с персонажем.
- Звук: подразумевается мощный удар/whoosh на стяжку и взрыв
- Грабли: нельзя останавливать вращение карт (должны крутиться даже стоя на месте); запрещено размытие — держать резкость; дымное кольцо одно, без частиц (три варианта отклонены).
- Demo: ../video-shotcraft/skill/demos/transition/card-flock-tumble/CardFlockTumble.tsx

### circle-match-iris · transition
- Суть: световой круг раскрывается из круглого элемента на экране (аватар/иконка), внутри него растёт круглый график — матч-кат «этот кружок стал этим графиком».
- Триггеры: было→стало / демонстрация интерфейса / результат-финал
- Энергия: средняя-высокая · Длительность: ~4.7с
- Вертикаль: с адаптацией (координаты якоря считаны с конкретного макета, пересчитывать под каждый экран отдельно)
- Зона: применим только к info-zone, если якорный круглый элемент лежит в этой полосе; персонаж не участвует
- Звук: не указан явно
- Грабли: два центра круга обязаны совпадать пиксель в пиксель, иначе видно смещение; якорь должен быть настоящим кругом, не скруглённым квадратом.

### color-block-step-wipe · transition
- Суть: два жёстких пиксель-геймовых прыжка цветного блока — А) из центра ступенчато на весь экран, B) по диагонали из угла, попутно тащит карточку.
- Триггеры: переход между мыслями / связка-объединение
- Энергия: средняя-высокая (за счёт рывков, не скорости) · Длительность: A ~2.5с, B ~1.5–2с
- Вертикаль: с адаптацией (геометрия простая, пересчёт несложен)
- Зона: весь кадр — блок заливает экран целиком, в этом суть жанра. Не годится для темы с персонажем.
- Звук: жёсткая зависимость от звука — на каждый прыжок нужен щелчок/удар, без него читается как лаг плеера
- Грабли: никакой интерполяции/сглаживания ни в одном месте (сломает весь стиль); шаги не должны быть равномерны по времени — иначе читается как проседание кадров.

### cube-navigation · transition
- Суть: контент облеплен на 6 гранях куба, камера чередует крупный план грани и общий вид с углов — навигация по модулям как облёт объёма.
- Триггеры: перечисление функций / демонстрация интерфейса
- Энергия: средняя · Длительность: ~6.0с на полный облёт (шаг между гранями ~0.7–0.85с)
- Вертикаль: с адаптацией (перспектива/distance считаны под 1920×1080, нужен пересчёт под вертикаль)
- Зона: весь кадр — самостоятельная 3D-сцена, а не переход поверх текущего кадра. Не годится как переход между репликами; может стать отдельной вставной сценой без диктора.
- Звук: не указан
- Грабли: направление вращения (ry) обязано быть монотонным, иначе укачивает; смена числа граней требует пересчёта всей таблицы позиций камеры.
- Demo: ../video-shotcraft/skill/demos/transition/cube-navigation/CubeNavigation.tsx

### gradient-transition · transition
- Суть: не «переход между сценами», а живой фоновый слой — плавная смена linear/radial/conic градиента с узким кросс-фейдом между типами.
- Триггеры: другое (амбиентный фон, не привязан к конкретному смысловому биту)
- Энергия: низкая · Длительность: ~6.0с цикл (можно нарезать любой участок)
- Вертикаль: ок (чистый CSS-фон, аспект не важен)
- Зона: применим только к info-zone как подложка позади текста/графики, либо на весь кадр позади персонажа при затемнении
- Звук: нет
- Грабли: под передним планом слой нужно приглушать (opacity 0.6–0.8 или scrim), иначе радужный conic-сегмент съедает контраст; строка CSS перезаписывается каждый кадр — проверить производительность на большом экране.
- Demo: ../video-shotcraft/skill/demos/transition/gradient-transition/GradientTransition.tsx

### line-carry-transition · transition
- Суть: линия (например, прогресс-бар) дотягивается до края кадра, камера едет вслед за ней, линия на ходу очерчивает рамку новой сцены — переход без склейки.
- Триггеры: переход между мыслями / было→стало
- Энергия: средняя · Длительность: ~5.3с (сам проезд камеры ~2с)
- Вертикаль: с адаптацией (мир 3840px широкий, под вертикаль движение логичнее по Y, а не по X — переработка сцены)
- Зона: весь кадр — движение камеры по всему полотну сцены, не локальный элемент. Не годится для темы с персонажем.
- Звук: скрип пера по линии + лёгкий стук на замыкании рамки
- Грабли: фирменный приём — ≤1 раз за ролик, второй раз магия рассыпается; линия обязана расти с той же скоростью, что едет камера, иначе «отстаёт».
- Demo: ../video-shotcraft/skill/demos/transition/line-carry-transition/LineCarryTransition.tsx

### mosaic-reframe · transition
- Суть: 12 плиток контента непрерывно перестраиваются между тремя раскладками (строгая сетка → мозаика с акцентом → диагональный каскад).
- Триггеры: перечисление функций / демонстрация интерфейса
- Энергия: средняя · Длительность: ~6.0с
- Вертикаль: с адаптацией (три таблицы координат считаны под 92% контентной зоны 1920×1080)
- Зона: применим только к info-zone, если плитки скомпонованы в этой полосе; персонаж не задет
- Звук: не указан
- Грабли: нельзя заменять на transform:scale (ломает переразбивку); между сегментами нужен hold ≥0.2 иначе три раскладки сливаются в одну.

### page-turn-transitions · transition
- Суть: страница-как-предмет — А) куб-разворот на 90° (грани смежные), B) распашные «ворота» рвутся пополам и уезжают, новая страница заходит снизу.
- Триггеры: переход между мыслями / было→стало (B — смена решения)

- Вертикаль: с адаптацией (геометрия куба/половинок под 1920 ширину)
- Зона: весь кадр — обе страницы физически занимают весь экран. Не годится для темы с персонажем (используется ≤2 раз за ролик как «глава», не для фразовых границ).
- Звук: не указан явно
- Грабли: обе стороны нуждаются в ≥30 кадрах статики до/после, иначе «телесность» тонет в движении; не более 2 раз за ролик.

### print-texture-transitions · transition
- Суть: капля чернил падает и растекается органическим пятном, «съедая» старую сцену и открывая новую сквозь рваный край.
- Триггеры: переход между мыслями / другое (для «бумажной» стилистики)
- Энергия: средняя · Длительность: ~4–4.5с (растекание ~1.8–2.7с)

- Зона: весь кадр — маска растекается по всему экрану; частично применимо с адаптацией, если ограничить маску только info-zone (пропадёт ощущение «затопления», но переход останется читаемым)
- Звук: не указан явно
- Грабли: старое лицо/лого сквозь шум читается как баг, а не фактура — избегать высокоузнаваемых элементов под маской; после заливки маску нужно снять, иначе subpixel-дрожь не даёт настоящей статики.

### shot-transitions · transition
- Суть: справочник из 6 техник смычки кадров (flash-cut, тёмный перелёт, расфокус-эстафета, чёрная карта, whip-pan, mask-wipe) — выбирается по перепаду энергии между соседними кадрами.
- Триггеры: переход между мыслями (весь набор — словарь связок между смысловыми битами)
- Энергия: n/a (техника-карта) · Длительность: A ~0.3с, B ~0.7–1.1с, C ~0.7–1с, D — по хронометражу главы, E ~0.27с рывок + hold, F ~1.5с
- Вертикаль: с адаптацией — геометрия A и E (flash-cut, whip-pan) простая и легко пересчитывается; B/C/D/F сложнее
- Зона: A и E можно ограничить полосой поверх info-zone, если белая вспышка/смаз лежат только сверху; B/C/D/F требуют изменения всей сцены → весь кадр
- Звук: A/B/C не указаны явно; D — по типографике; E — whoosh на смаз
- Грабли: один шов = один приём, техники не комбинируются на одной склейке; кадры под приём закладываются на этапе раскадровки, иначе бюджет крадётся у соседних планов постфактум.
- Demo: A — template/src/aifl/Main.tsx; E — demos/transition/shot-transitions/WhipPanReal.tsx, WhipBrakeReal.tsx; F — demos/transition/shot-transitions/MaskWipeReal.tsx, PortalWipeV2.tsx

### tear-streak-transitions · transition

- Звук: подразумевается глитч-эффект/статик
- Грабли: только цельные горизонтальные полосы, никаких «осколков» (три альтернативы отклонены); склейка обязана прятаться в затухании тряски, а не на статичном кадре.

### transition-hidden-cut · transition
- Суть: три способа спрятать жёсткую склейку за 1–3 кадра — A) карточка со смазом пролетает через кадр, B) две половины экрана стакиваются со вспышкой, C) тёплый блик выжигает старую сцену.
- Триггеры: переход между мыслями / другое (B — сравнение-контраст, «против»)
- Энергия: n/a (техника-карта) · Длительность: A ~0.47с (в бюджет), B ~0.33с (в бюджет), C ~2.3с (за бюджетом)
- Вертикаль: с адаптацией — A и B простая геометрия под вертикаль; C — диагональные блики под 1920 ширину
- Зона: все три — весь кадр (смаз через весь экран / раскол пополам по всей высоте / диагональный блик через весь кадр). Персонаж будет перекрыт/расколот в каждом. Не годится для темы с персонажем.
- Звук: не указан явно, но просится под A и B (whoosh/удар)
- Грабли: A требует, чтобы смаз-карточка реально перекрывала весь экран, иначе видна щель со старой сценой; B без пары «против» в смысле — просто раскол без причины; одна склейка = один приём, не комбинировать с flash-cut.
- Demo: ../video-shotcraft/skill/demos/transition/transition-hidden-cut/ (InvisibleCut.tsx / LightLeakBurn.tsx / VersusSlam.tsx)

### transition-travel · transition
- Суть: два «проездных» перехода — A) элемент детальной карточки сжимается и садится точно в свой слот на общей панели, C) огромная буква заголовка становится дверью в новую сцену.
- Триггеры: переход между мыслями / было→стало (A — деталь→сводка)
- Энергия: n/a (техника-карта) · Длительность: A ~1.2с, C ~2с
- Вертикаль: с адаптацией (координаты слотов и буквенных «проёмов» считаны под конкретный макет 1920×1080)
- Зона: A применим только к info-zone, если и деталь-карточка, и слот-панель лежат в этой полосе; C — весь кадр, буква проходит через весь экран, не годится для темы с персонажем
- Звук: не указан
- Грабли: A требует пиксель-точных координат слота, иначе читается как «долетело и притёрлось», а не «точно село»; C — координаты буквенного проёма плывут при смене шрифта/слова, проверять по первому кадру рендера.

- Энергия: средняя-высокая · Длительность: ~4.6с
- Вертикаль: с адаптацией (координаты компонентов заданы под конкретный макет)
- Зона: применим только к info-zone — страница-макет умещается в контентной карточке
- Звук: не указан
- Грабли: линия обязана закончить проход ровно в момент установки последнего блока, иначе «сканирование управляет сборкой» не читается; при смене шаблона все Y-координаты падения пересчитываются заново.

### slam-entrance-moves · effects
- Суть: три вида «тяжёлого» появления карточки — A) рыбий-глаз перспективный залёт со щелчком выравнивания, B) KPI-карта падает с 2.5-кратным увеличением и «впечатывается» с кольцом+пылью+тряской экрана, C) B + соседние карточки видимо толкаются волной удара.
- Триггеры: A — появление объекта-героя; B/C — большая цифра / результат-финал
- Энергия: высокая · Длительность: A ~0.6–0.8с (в бюджет), B ~0.2–0.3с падение + отдача ~0.5с, C — то же + волна по соседям
- Вертикаль: ок для одной карты, простая геометрия
- Зона: применим только к info-zone — карта/KPI-блок локальны, но тряска экрана по умолчанию трясёт весь кадр, включая персонажа — нужно ограничить тряску контейнером info-zone (адаптация)
- Звук: обязателен звуковой удар синхронно с падением — без звука читается как «подёргивание»
- Грабли: тряска экрана — общий ресурс на кадр, нельзя использовать вместе с другими «трясущими» приёмами в этом же кадре; не более 2 «ударных» появлений на весь ролик.
- Demo: ../video-shotcraft/skill/demos/effects/slam-entrance-moves/ (ImpactBurstKit.tsx / KanadaPerspectiveSnap.tsx / ScoreSlam.tsx)

### spotlight-sweep-moves · effects
- Суть: три способа «проявления» UI из полной темноты лучом прожектора — A) луч идёт слева направо и гасит за собой, B) луч скользит вдоль края панели с лиловым свечением, C) круг света из угла равномерно расширяется на весь экран.
- Триггеры: акцент «смотри сюда» / «как работает X» (постепенное открытие интерфейса)
- Энергия: средняя-низкая · Длительность: 3.5–4.5с на приём
- Вертикаль: с адаптацией (движение луча/радиус заданы под 1920×1080 систему координат)
- Зона: A/B применимы только к info-zone (проявляют конкретную панель на тёмном фоне — подходит теме dark-amber); C расширяется до заливки всего экрана — весь кадр, не годится с персонажем
- Звук: не указан
- Грабли: строго равномерная скорость луча/радиуса — любое ускорение читается как «у света есть намерение», ломает ощущение прожектора; лиловое свечение обязано идти строго вдоль реального края UI, иначе теряется «касание интерфейса».

## Звёзды пакета

Топ-5 приёмов из этих двух категорий именно под вертикальный говорящий ролик 40–90с с постоянным персонажем и полосой субтитров:

1. **fui-hud-moves B (reticle-lock-on)** — единственный приём, который одновременно укладывается в бюджет 0.4–0.8с (захват ~0.33–0.4с), физически ограничен целью внутри info-zone и даёт ровно то, что нужно разговорному ролику про AI-инструменты — акцент «смотри сюда» на конкретном элементе интерфейса, не трогая персонажа.
2. **card-flip-reveal** — компактная карточка-переход «функция → результат», идеальна для связки «было→стало» между двумя мыслями в сценарии, полностью локальна к info-zone, длительность одного переворота (~0.9с) почти укладывается в целевой бюджет.
3. **icon-performance-moves A (pop-burst-confirm)** — самый точный тайминг в пакете (~0.67с, буквально в середине заданного окна 0.4–0.8с), готовая пунктуация под «готово/сработало», не требует полноэкранных эффектов.
4. **line-boil** — единственный приём, который вообще не конкурирует с ограничениями зоны и тайминга: не переход, а «страховка от статики» на любом долгом hold заголовка или графика, ноль риска для персонажа и субтитров.
5. **scan-bracket-sweep** — лучшее решение для сквозного триггера «как работает X» / демонстрация интерфейса: спокойная энергия (подходит тону говорящей головы, не соревнуется с голосом за внимание), полностью локализуется в info-zone как карточка документа, не требует тёмной темы.
